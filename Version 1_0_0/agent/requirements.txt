# ============================================================================
# Agent Requirements
# ============================================================================
#
# Migration strategy:
#   Phase 1  -> Contracts / Transport Interface Foundation
#   Phase 2  -> Core / Dispatcher / Command Execution Separation
#   Phase 3  -> Legacy Kafka Transport Integration & Semantics
#   Phase 4  -> Persistence / SQLite Spooler
#   Phase 5  -> Gateway HTTP/mTLS Transport
#   Phase 6  -> Reliability / Retry / Circuit Breaker / Idempotency
#   Phase 7  -> Security / Health / Observability
#   Phase 8  -> Windows Service / Deployment
#
# Important:
#   Dependencies are grouped by the migration phase in which they are
#   actually required. Existing Legacy dependencies remain available until
#   the corresponding migration phase proves that they can be removed.
#
# Do NOT add a dependency merely because a future target-architecture
# component exists. Add it when the corresponding phase actually requires it.
# ============================================================================
# استراتژی مهاجرت پروژه به ۸ فاز تقسیم شده است.
# وابستگی‌ها فقط زمانی اضافه می‌شوند که فاز مربوطه واقعاً به آن‌ها نیاز داشته باشد.
# وابستگی‌های قدیمی (Legacy) تا زمانی که جایگزین‌شان به‌طور کامل تأیید نشده، حذف نمی‌شوند.

# ============================================================================
# FUTURE / CONDITIONAL DEPENDENCIES
# ============================================================================
#
# The following are intentionally NOT included:
#
#   redis
#   sqlalchemy
#   psycopg
#   asyncpg
#   cryptography
#   prometheus-client
#   tenacity
#   httpx
#
# Reasons:
#
#   redis
#       No Redis implementation currently exists.
#
#   sqlalchemy
#       Persistence currently uses sqlite3 directly.
#
#   psycopg / asyncpg
#       PostgreSQL is not currently part of the implemented persistence layer.
#
#   cryptography
#       Current certificate/TLS implementation uses the standard-library
#       ssl module.
#
#   prometheus-client
#       No Prometheus metrics implementation currently consumes it.
#
#   tenacity
#       Retry/backoff is implemented with the Python standard library.
#
#   httpx
#       Gateway implementation currently uses requests.
#
# ============================================================================
#
# Dependency policy:
#
#   1. Every external dependency must have an actual consumer.
#   2. Do not add dependencies for planned architecture only.
#   3. Prefer Python standard library when it satisfies the requirement.
#   4. Keep legacy dependencies until their replacement is verified.
#   5. Remove dependencies only after static and runtime verification.
#   6. Security-related dependencies must be justified by the actual
#      implementation rather than by theoretical future requirements.
#
# ============================================================================
# وابستگی‌هایی که عمداً اضافه نشده‌اند (چون هنوز مصرف‌کننده واقعی ندارند).
# سیاست کلی: فقط وابستگی‌هایی اضافه شوند که واقعاً استفاده می‌شوند و اولویت با کتابخانه استاندارد پایتون است.
